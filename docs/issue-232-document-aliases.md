# One document, one research attention slot

Issue [#232](https://github.com/tang-vu/keryx/issues/232) observed Quick selecting
both a free public GitHub original and an ordinary registered RSS copy of the
same article URL. The second channel incurred an access toll but contributed no
qualifying citation. The article's useful content and the registered payment's
recorded state do not establish independent creator adoption or finalized Circle
batch completion.

The shared TypeScript research selector now groups candidates by a conservative
canonical document location. One location can occupy at most one portfolio
attention slot and make one predicted claim-coverage contribution. Bounded
optimization admits distinct documents before filling remaining candidate space
with alternate delivery channels. Meaningful query parameters, version paths
and different publishers remain separate; fragments and tracking parameters use
the existing public-reader normalization.

Each delivery channel keeps its own model-proposed targets, expected value,
asset/source IDs, content version, authoritative registry/offer price and reward
eligibility. The selector chooses the useful channel inside the existing money
and attention bounds; equivalent routes prefer free public delivery. It never
copies the registered channel's target coverage to a public proposal, promotes
a model SKIP, or turns a below-attention public proposal into a read. A selected
public route has zero article access toll and zero creator citation reward.
Unselected aliases explain that outcome in the decision ledger. Model, search,
service and any applicable operating allocation remain separate costs.

Canonical location is selection metadata, not proof of identical bytes, current
revision, ownership, authorship, rights or independent corroboration. A URL supplied
by a caller never supplies payout authority. Registered delivery and rewards still
pass the existing active/verified source, rights, source-claim, exact item/version,
registry terms, integer budget and qualifying-evidence gates. A stronger registered
proposal can still win; its access receipt and any evidence-qualified citation
reward remain separate. An unqualified paid read may legitimately earn no citation
reward. Failed or changed delivery keeps the existing uncertainty and recovery
rules; this update does not reinterpret historical payment evidence.

The read path also refuses an already gathered location before another channel
can read/pay, including Deep gap recommendations. Public redirects are checked
against gathered document locations after bounded extraction. A newly observed
redirect can leave an initial portfolio selection unread; the final outcome reports
that honestly and no unused article toll is paid. Same-location revisions are
conservatively treated as one document, rather than certified as independent
corroboration. Comparing explicit versions requires distinct admitted document
identities and qualifying excerpts.

Offline synthetic fixtures exercise ordinary registered RSS plus public web/RSS
aliases, an independent document, same-utility public preference, stronger paid
delivery, retained paid item/version identity, budget/attention/public-SKIP gates,
withheld unsupported citation rewards, redirected aliases and Deep recommendations.
Gateway and registry effects are injected; these checks do not call a model,
search provider, live payment service or production database and do not prove live
settlement. Production validation, required CI/review, deployed commit and package
readback remain release-owner gates.

The grouping applies to callers of the shared `runAgent` pipeline: hosted web/chat/
embed, API/OpenAI, hosted MCP, human CLI and bots, and admitted A2A/buyer research.
Public and private effects keep their existing boundaries; a private job gains no
external discovery. Desktop/Operator, extensions and stdio buyer controls keep their
existing task/handoff/purchase roles. No public request, payment, receipt or storage
schema, custody, signer, nonce, session cap or shared Rust cutover changes here.
