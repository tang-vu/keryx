# Explicit way-to-action requests

Ordinary callers can ask for a practical method with “Is there a practical way
to…” or “What's a quick way to…”, without naming a plan or using “How should
we…”. The finite English grammar recognizes an action across subjects and keeps
the complete original request as the version2 work-product review criterion.
Recognizing the request supplies neither missing facts nor execution authority.

Existing labels retain precedence. Quoted/code/source-attributed text, explicit
no-method instructions, dictionary and historical questions, protected answer
formats, prepared requests, private scope and the separate teaching rollout keep
their existing boundaries. Recognition is intentionally finite, not a semantic
classifier for every possible method question.

Proposed steps use the existing synthesis and independent review, factual premise
binding, final ledger and receipt/export path. Unsupported or rejected proposals
remain withheld. No extra model call, source read, reward weight, payment action,
activation or new public interface is introduced. Web/API and their CLI/MCP and
desktop callers share this existing backend contract; no deployment is implied.
If no original source is successfully read, the existing unsupported answer
remains and no draft generation is attempted.

Deterministic history replay measures recognition only. Synthetic orchestration
checks establish contract and financial preservation, not real-model usefulness,
source truth or a representative quality rate.
