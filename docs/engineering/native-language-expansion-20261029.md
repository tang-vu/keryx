# Five additional ordinary answer languages

This source extends ordinary answers from six canonical languages to eleven:
`en`, `vi`, `pt`, `es`, `fr`, `zh-Hans`, `de`, `ja`, `ko`, `hi` and `id`.
`pt-BR` remains a request alias of `pt`, never observed-language evidence. The new
languages are German, Japanese, Korean, Hindi and Indonesian. Language support
here is bounded by the ordinary answer producer and each consumer's existing role;
it does not establish complete UI translation, human approval or a deployed release.

## Request and observation

The original question can contain a finite positive command such as “Answer in
German.”, “Antworte bitte auf Deutsch.”, “日本語で回答してください。”,
“한국어로 답변해 주세요.”, “कृपया हिंदी में उत्तर दें।” or
“Tolong jawab dalam bahasa Indonesia.” These commands are examples, not a general
language detector. Clause boundaries, literal quotations, negation and command
order remain significant. A later supported command wins; a later recognized
unsupported request clears earlier intent. English reversion uses the admitted
native forms. Retained and legacy producer grammars remain unchanged.

Generation receives the selected language before the existing independent
evidence-review call. That same bounded reviewer may observe the eleven canonical
codes or `UNKNOWN`; no extra translation or reviewer call is added. Shared Han
characters alone do not prove Japanese or Simplified Chinese. Missing, mismatched,
aliased, cloned or mutated observations cannot authorize delivered statements.
Separately admitted source evidence and reward eligibility retain their own gates.

The native ordinary renderer covers reviewed summaries, excerpt-only answers,
missing targets, incomplete synthesis, safe short bullets, confidence, integration
proposals, supplied-original status and manual recovery. It keeps literal targets,
quotes, URLs, fragments, citation markers, codes and qualifications. Hindi danda
already ends a statement; adding a Latin full stop would alter the delivered pair.
PDF notices use the existing source-bound machine draft and observed page/text
scope, without claiming OCR, image interpretation or complete-document coverage.

A language packet requires the actual renderer and all delivered reviewed
statements to agree, then binds the exact final UTF-8 answer and completed query.
No existing history is relabelled. Private, execution-limited, teaching and other
separately admitted producers retain their existing boundaries. Financial or
operational paragraphs outside the observed renderer keep whole-answer proof
unknown. Empty public discovery can show native recovery copy without inventing
reviewed answer-language evidence or initiating another read or purchase.

The canonical English financial, funding, settlement, review-boundary, consent
and custody copy remains authoritative. There is no new signer, nonce, allowance,
budget, retry, source eligibility or payout authority. Source-owned `payTo`, atomic
spend reservations and exact integer micro-USDC allocation remain authoritative.
Native output still enters the existing attribution model call; fixtures with
fixed allocations do not establish identical live weights or model usefulness.

Full Vietnamese and Simplified Chinese UI machine drafts retain their source
bindings. The other eight existing entry previews retain their authored floor.
Every preview remains a machine draft with no human approval; the shipped UI
locale remains English. Financial and consent review is a separate gate.

## Public image text and acceptance

Public report, creator and wanted cards bundle pinned, unmodified, licensed local
Japanese, Korean and Devanagari fonts alongside the existing Latin, Chinese and
math faces. Script coverage chooses glyphs, never answer language. Private,
unlisted, missing and refused reports retain generic metadata before shaping.

Satori could render valid Hindi PNGs with the wrong conjuncts and vowel order.
Devanagari text therefore uses the local Sharp/Pango/HarfBuzz shaper before image
layout. Text is literal escaped markup, at most 512 UTF-16 code units, with bounded
font size, color, width, height, pixels and rendering time. A native Hindi caption
is shaped even when its original question is English. Other scripts return their
original string nodes. Local font selection includes the displayed native serial
and citation captions even when the original question is English, so these labels
do not require the renderer's external font fallback. Sharp 0.35.5 was already locked through Next; making it a
direct dependency changes no locked package version, resolved URL or integrity.
Fresh hosted installation and production tracing remain required acceptance.
Font sources, licenses and hashes are recorded in [the font inventory](../../app/fonts/og/README.md).

Focused offline checks exercise the actual engine/reviewer, orchestrator, bound
readers, real Desktop renderer, buyer recovery, scoped bot/email consumers and
public image routes. The existing production-CSS browser check retains previous
scenarios and adds five independently observed synthetic answers at 320 and 1366
pixels, preserving four statement/original pairs in three bullets, keyboard
citations, language tags and viewport bounds. These synthetic observations do not
establish native-speaker approval or live model quality.

The controlled 48-trial study must execute again for the changed application and
lock inputs; fingerprints alone cannot reproduce its metrics. Required exact-head
PR `build-and-test`, applicable platform/domain checks, and direct review of actual
native browser/image artifacts remain separate gates. Existing ROOT/Circle owns
exact-main publication and the combined runtime release. No production identity,
deployment, funding renewal or human translation approval is claimed here.
