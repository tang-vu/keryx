# Public-trial funding observations

New mainnet web trials record the server's known treasury sponsorship separately
from who the reader is. The observer runs only after the ordinary handler has
completed admission and constructed its no-browser real hosted gateway. It reads
the already-selected payer without funding, signing, submitting or reconciling.
The network, configured origin, server query ID and selected payer are bound into
a domain-separated observation digest. This is server-stamped provenance, not
independent settlement evidence or a supplier invoice.

A reader with no reviewed outside-person evidence remains `unknown`, including
a signed-in wallet. Existing verified configured team membership stays `team`.
Authenticated controlled bot activity stays `scripted`. The known hosted trial
funding is `team`; it never becomes an independently funded outside purchase.
Offline, browser-funded, unobserved or incompatible-network paths retain unknown
funding. Failed observation cannot change admission or payment behavior.

Successful runs and saved pre-discovery planning failures use the same local
classification capability. Public request JSON cannot supply it. Serialized
copies lose the capability. Historical rows are not rewritten or inferred from
their old `fundingOwner` field, and no receipt or liability changes.

This slice covers the ordinary web trial adapter only. API/MCP prepaid, private,
browser-session, CLI, desktop, extension and bot-specific funding roles retain
their existing contracts. Their records require separately proven funding facts;
no parity claim or outside traction is inferred from these web observations.
Existing settled-payment and acceptance rules still decide the public metrics.
