# Research stream failures after terminal delivery

The browser keeps a received completed report or explicit SSE error when the
response reader subsequently rejects. A transport exception cannot revoke an
already delivered answer, replace the server's diagnostic, change confidence or
reinterpret the original payment records.

If no terminal event arrived, both a failed fetch and a rejected reader use the
existing interrupted-delivery guidance. A current request's `AbortError` is an
interruption too; explicit Stop/Reset and replaced requests are excluded by the
existing controller identity and aborted-signal checks. An interruption does not
prove that server research or payments stopped. Recovery offers the existing
manual original-report link only for valid public or unlisted metadata. It makes
no additional request, signature or automatic retry and fabricates no saved ID.

Private report delivery and anonymous claim-credential delivery remain distinct.
The completed private report stays visible in its existing owner/document scope.
A claim credential still requires the existing matching saved report, packet and
clean transport completion. A rejected transport forgets that credential and
retains the existing lost-handoff behavior, even when the report arrived first.
No storage, server, settlement, signing or supported-surface contract changes.
