# Arabic ordinary answers and original reading

Ordinary research accepts explicit Modern Standard Arabic directives such as
`أجب بالعربية.` and `Answer in Arabic.`. Exact `ar` is the thirteenth canonical
presentation language; the existing `pt-BR` request alias remains an alias of
`pt`. Regional labels can select client labels but cannot attest generated prose.

The finite directive grammar retains original question bytes. It handles Arabic
question/semicolon boundaries and later English instructions; negations, quoted
examples, title wrappers, URLs and partial language names do not authorize a
language change. Retained and legacy directive grammars remain separate.

Generated Arabic statements use the existing bounded generation and independent
review path. A request, prompt, JSON property or Arabic script alone is not a
language observation. Persian, Urdu and ambiguous prose remain unknown. Runtime
observations remain bound to the exact reviewed statement, and completed language
packets remain bound to final answer bytes. Existing evidence admission, source
ownership, payment and reward gates still decide their respective authority.

The authored catalogues contain 203 machine-draft strings for ordinary answers,
PDF scope, recovery, reports, neutral clients and bots. Critical financial,
settlement, custody, privacy and consent copy keeps its existing English authority
and named-human review requirements. No Arabic web UI locale is enabled here.

Known generated Arabic prose reads right to left. Unknown originals keep `und`
and automatic direction. Web and Desktop readers share literal technical-token
isolation, so URLs, angle/brace syntax and English references remain readable
without injecting Unicode controls or changing original stored text. Desktop
saved, unsaved and sponsored originals acquire no language attestation from the
viewer preference. Financial and submission controls retain their existing roles.

CLI, API, stdio/remote MCP, Desktop and bots expose the existing finite `ar` label
choice. Label choices do not translate a retained answer. For generated Arabic,
the caller supplies an explicit directive in the original ordinary question.
Recorded display uses Latin digits and the Gregorian calendar through the
existing formatter; signing uses the original exact decimal micro-USDC path.
The extension retains the byte-identical browser-safe formatter and hosted-reader
handoff.

Focused validation covers all six Arabic plural categories, unknown/mismatched
language and malformed amounts, independent observations, original-value
placeholders, API refusal/authentication boundaries, actual Desktop selectors and
responsive Chromium readers. An inspected Desktop capture exposed mirrored angle
syntax; sharing the accepted technical-token isolation fixes it. The controlled
study was reproduced for all 48 offline trials against 505 source inputs: every
non-source-fingerprint result stayed identical and outbound attempts were zero.
This is a controlled regression result, not real language-quality or settlement
evidence.

Full current-source PR/domain/platform checks and direct hosted image inspection
are still required for merge. Runtime/package/installer delivery remains a
separate coordinated batch. These source changes do not establish deployment,
human translation approval or a complete RTL interface.
