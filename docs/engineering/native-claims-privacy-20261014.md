# Native ownership and privacy on the selected application store

The native ports use the genuine verified connection and the complete source-known
19-table bundle. They accept no caller guard, fixture clock, ownership fallback or
second connection. The original claim token, session, single-use, byte fingerprint,
privacy, revision, audit and financial-retention journal bodies remain shared with
the ordinary constructors. Ordinary enrolled-store refusals remain intact.

Trusted native opening installs only the existing two bounded pure ownership
projections. The application wrapper cannot register functions or extensions.
Claims and ownership bind the native network; private actor bindings do too.
Readonly mutation/export refuses before SQL, leaving healthy reads available.
Actual SQLite busy/locked failures remain temporary; provenance and internal SQL
guard failures permanently retire the affected borrowed port and connection.

The facade captures the existing claims/privacy flags once. Enabling either needs
the complete native policy, and privacy also uses a genuine ownership reader.
Private reads retain the existing evidence presentation after authorization;
original owner exports and claim fingerprints retain their recorded bytes.
Existing public queries/memory/offers route through the same captured privacy
capability. No historical sidecars or claims are backfilled, no prior activity is
published, and erasure retains the existing financial records and counters.

Sixteen genuine native cases and focused TypeScript checking passed. They cover
original bytes and payment ownership, claim single use and session revocation,
network/origin binding, private/default/public access, owner mutations/export,
financial erasure retention, readonly refusal, actual writer contention, internal
guard revocation, and the actual frozen writable/readonly application facades.
Independent source review accepted the unchanged original journal bodies.
