# Native first-use research guidance

The Spanish, Brazilian Portuguese, French, German, Japanese, Korean, Hindi and
Indonesian previews previously lacked the keyboard/depth instructions, metadata
handoff labels, tour controls and log-reading guidance that surround the question.
The actual tour also inherited the selected interface language for its English
spending explanation. Valid document-level geometry did not catch French and
Portuguese depth names overflowing their own radio-option borders at 320px.
Enlarged text also exposed a guide trigger covering the introductory kicker and
a clipped Portuguese submit label.

## Source behavior

Each of these eight partial catalogues adds 23 bound entries: six composer
instructions/labels, eleven tour leaves and six decision-log leaves. That is 184
new entries and 196 authored entries per catalogue. They retain `machineDraft`
and `review:null`. English remains the only shipped UI locale; the existing
preview notice, opt-in boundary and conservative critical-copy filter remain.
Generation requires at least 16 admitted core-inline and 17 admitted research-flow
entries, alongside the existing namespace floors and source/template binding.

The existing `UiMessage` renderer marks each displayed tour/log leaf with its
actual authored language. Unreviewed spending explanations and financial states
remain English and expose `lang="en"`. Actual report/trace messages, questions,
source names, rationales, amounts and URLs are never passed through these new
translation leaves. Account/browser preference authority is unchanged.

Shared French/German question labels retain their existing translations instead
of falling back to English when catalogue aliases disagree. The example controls
have a named `group`. Metadata links and example-group labels
expose the language of their own accessible names. Opening options, changing
depth, navigating the tour and closing it preserve the unsent question and the
original metadata handoff URL. The guide neither submits a question nor signs,
funds or retries a request.

Depth options use a wrapping flex layout with a ten-rem basis. They share a row
when space permits and retain their full names on narrow surfaces. Inner content
can wrap with enlarged text. Native radio values, input names, handlers, source
caps, model settings and server admission keep their existing meaning.
The hero guide participates in normal wrapping flow, and its trigger stays within
the available width. The submit label and icon wrap inside the button. This keeps
the complete text visible at enlarged sizes without changing submission behavior.

## Surface and delivery boundaries

Web and the desktop web view use the shared composer, tour and console. API, CLI,
remote/stdio MCP, extension and bot contracts retain their established roles and
ordinary answer-language behavior. UI labels do not establish answer provenance
or modify original targets, quotations or receipts. Source/financial admission,
consent, custody and all payment authority are unchanged.

This is partial preview coverage, not human approval or completion of every
language/user journey. ROOT/Circle retains the coordinated runtime/publication
batch, retained originals and prepared-cutover gates. A successful source PR does
not prove that the new controls are live in production.
