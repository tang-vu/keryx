# HTML evidence context — October 8, 2026

App 0.27.34 is a source candidate. Production deployment and a separately
authorized usefulness trial remain release gates. The earlier owner-operated
mainnet QA batch is closed; these changes grant no further spending or model calls.

## Problem and behavior

The saved RFC4180 HTML reproduction selected physical lines, losing a quoted-field
condition and its continuation. The Spanish NASA reproduction retained heading
labels but omitted the following rotation and illumination explanation. A TOC
anchor and a substantive h3 contained the same label.

The existing inert parser now records observed preformatted regions and literal
h1–h6 in its final extracted text. CSS classes and TOC links do not become heading
roles. Within observed pre regions, physical wraps share a paragraph boundary view;
blank separators remain separate. A deeper indented example stays with its numbered
preformatted item. Selection, omission flags, strict quote eligibility and review
context use these shared groups. Quotes always slice the original extracted body
at exact UTF-16 offsets. This does not interpret a rule's meaning or establish support.

Short names explicitly quoted in the question can nominate matching actual HTML
headings and contiguous following text, including when the surrounding question
uses another language. Leading numbered heading identities remain distinct.
At most four matches are sampled, using the first and last two when duplicates
exceed the cap. This is bounded retrieval, not full section coverage. Existing
URL-fragment matching retains its unique plain-line semantics.

## Bounds and provenance

The 200,000-character scan, 2,000-character selected context, nine windows,
600-character candidate windows, 16 candidates per target and shared nomination
ceiling remain. New named hints use at most 1,200 context characters and reserve
both one 600-character lexical window and one selection slot after the opening.
Established fragment priority is unchanged.

Metadata contains at most 512 regions. Excess roles are omitted and labeled
`htmlStructureLimited` in reasoning context, preserving the readable body. Existing
worker heap, raw bytes, element/depth, normalized bytes, timeout and output caps
remain. Headings crossing the extraction edge are withheld. A split surrogate
pair is withheld at that edge rather than returned malformed: this exceptional
prefix changes the body/version from the older 60,000-unit cut.

The parent validates the exact returned text SHA256, UTF-16 length, bounded ordered
nonoverlapping ranges per kind and role cap. It freezes a clone and enrolls it
in a process-local WeakSet only at the validated isolated-worker boundary.
Gathered HTML public reads also require the observed extraction kind and matching
contentVersion. Changed bodies/versions and JSON copies cannot activate layout.
Historical/layoutless sources keep their prior behavior; no restoration migrates
their quote eligibility. PDF retains its existing boundary policy. Layout is
internal and does not become public citation or receipt authority.

## Acceptance and limits

Regression fixtures cover conditions and examples, complete wrapped quotes and
high-support suffix rejection, original review offsets, numbered and duplicate
headings, cross-language named retrieval, lexical slot reservation, entity-generated
CR, layout forgery/mutation, bounded roles and Unicode truncation. Existing selector,
fragment, PDF, quote, ledger and reader checks remain required. Production build
and assembled traced-worker extraction validate distribution of the actual worker.
An actual minified Ask-route fixture checks process-local enrollment across the
built reader, gathered-source, selection and strict-quote modules; JSON cannot
restore that enrollment. It performs no model or external request.

Retained downloaded HTML is replayed without new retrieval or model calls. The
RFC and NASA bodies remain byte-identical to their captured extracted bodies.
The original RFC question now retains rules6–7 with their examples and standards
status; the rule5 condition is tested under an explicit unquoted-value target.
NASA retains the observed h3 and the required rotation, hemisphere and sunlight
prose. These are source-selection observations, not a claim of useful final answers
or independent traction. No old issue or live trial is relabeled as successful.

OpenAI-compatible research, CLI, remote and stdio MCP, desktop forwarding,
extensions and bots. Their input, answer, citation and receipt contracts stay
compatible; no client-specific extraction copy or package version bump is needed.
Deployed commit and published client/installer inventories must still be verified
before claiming synchronized delivery. Saved reports retain their original content.

Independent semantic review, ledger support thresholds, source identity and

read, heading match or quote option is not a settlement receipt or coverage proof.
