# Isolating an expired failed canary from interactive research

The owner-funded October 6 Operator trial can fail without having delivered its
paid original. Its permanent claim and provider reservations must remain intact.
Holding unrelated interactive research indefinitely does not recover that order.
An explicit private metadata operation can therefore narrow this hold to Operator
after fresh native verification. It does not fulfill or refund the original.

## Admission and authority

The initial recovery supports only an expired additive fulfillment authorization,
an exact local/native permanent claim, no prepared/delivered result, and fewer than
three additive model holds. Three calls may still prepare metadata after expiry
and must use the prepared-result recovery path instead. Existing source bodies,
authorization, failed-order snapshot, inbound settlement and both raw provider
ledgers are verified and remain immutable. Holds remain reservations; provider
invoices are not inferred.

`canaryExecutionPaused` still holds Operator, all new paid A2A/private admission,
incoming settlement and original replay. Ordinary public runs, search and model
transports use `canaryResearchPaused`. A2A, private, paid scholarly and the retained
original ID cannot enter the ordinary exception. It grants no model allowance,
payment permission or schedule: existing interactive compute admission, quota,
browser consent, session caps and payment authority remain required independently.

A protected separate marker binds the full original authority and expired partial
claim/ledger. It says delivery is unresolved, the original is neither delivered
nor refunded, and Operator is paused. Public responses expose only the existing
research availability category, never private claim, question, path or ledger.
Missing, extra, changed, malformed or insecure files fail closed. This retained
observation follows the existing trusted-operator threat model; it is not a live
native database audit and does not protect against privileged operator tampering.

## Private operation and restoration gates

Use a clean reviewed release and the enrolled readonly native storage adapter:

```text
npm run canary:isolate-research -- inspect
npm run canary:isolate-research -- isolate --evidence-sha256 <exact inspected digest>
```

Inspect verifies the existing failed original and permanent claim twice across
native awaits. Isolate binds the reviewed digest, stages and flushes a pending
record, obtains another native proof, then atomically publishes the allow record.
A pending or malformed directory keeps research held. Final publication flush
failure rolls the file back to pending. Repeated accepted metadata inspection is
idempotent; an ambiguous pending operation is inspection-only and must not be
overwritten or retried. No DB write, signer, provider request, payment, refund,
authorization renewal or fulfillment execution exists in this command.

The operational controller must positively drain supplier-capable writers and
hold every applicable role through publication. **Restore roles only after actual
CLI exit 0, complete captured streams, and exact accepted marker/readback plus
fresh native proof.** A failed/unknown command does not clear maintenance even if
a marker is visible: final flush and rollback can both fail. Preserve such evidence
and keep roles and boot startup held until separately reviewed recovery. Marker
presence alone is not a restoration receipt. Existing schedules remain held until
their independent role/source/cap gate passes; no new schedule is authorized.

## Supported surfaces and release acceptance

Web, widget, desktop, browser extension, CLI, API, OpenAI compatibility, bots and
remote/stdio MCP retain their shared interactive admission and availability
contracts. This is a server policy release; these thin clients need no changed
protocol or package. Operator/A2A/private business admission remains intentionally
separate and held, with the failed original still recoverable through existing
authenticated status paths. No public isolation or retry endpoint is added.

Focused regression coverage includes a real offline orchestrator run, ordinary
search/model guards, original-ID/A2A/private rejection, native claim disagreement,
expiry, three-call refusal, immutable old/new ledgers, tampering, native drift,
pending publication and final fsync failure. Release requires both TypeScript
graphs, lint/build, required CI and independent review, merged source deployment,
actual native metadata acceptance and deployed health/availability readback. A
read-only availability check establishes local admission state; it does not prove
current provider capacity or a successfully generated answer. Any live supplier
smoke must have its own applicable explicit budget authorization.
