## Source and role boundary

The ordinary opt-in quote menu can already offer a whole visible enumerated block
with at least two complete sentence spans, at most 240 UTF-16 characters, wholly
inside one selected contiguous passage. Original sentence choices and IDs come
first; alternatives use only remaining capacity within the 64-option menu and
1,200-character context caps. This change adds no choices or retrieval allowance.

A process-local WeakMap binds each constituent option to that exact whole item
only when the alternative is actually offered and the live HTML layout is observed
against the complete, nontruncated public body. Preformatted content, PDF,
partial/gapped selections, oversized blocks and copied layout metadata cannot
enroll. No source-specific vocabulary or semantic grouping rule is introduced.

The proof follows the server-resolved quote-span object through the existing
independent review. A statement inherits it only after the unchanged quote,
statement-support, accepted-marker and evidence-ledger gates pass. Consumption
rechecks the same observed layout object, source body, marker/source/item/URL/version identity, unchanged
statement fields and exact qualifying ledger identities. Copied options, spans,
statements or JSON cannot recreate it. Nothing is serialized into a receipt.

Presentation first preserves the existing shared-target and literal nested-quote
groups. A new structural edge joins only groups whose every member has proof for
the same item. Shared-target transitivity cannot pull another block into that
edge. Every admitted sentence retains its exact excerpt and citation; the final
count, target coverage, excerpt visibility, four-sentence and 1,200-character row
limits still decide whether compact output is allowed. Failure keeps the existing
target sections and unmet-format notice. This does not establish entailment,
truth, language correctness or a relationship between separately reviewed facts.

Quote options, proposals, statements and ledger JSON keep their existing shapes.
Support, payee, reward eligibility, allocation and payment authorization are
unchanged. Opt-in ordinary final answer text can change. Default menus and
finalization without a requested count retain their old output. Historical saved
answers, portable receipts and private originals are not regenerated or upgraded.
