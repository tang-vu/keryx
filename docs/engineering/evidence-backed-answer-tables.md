# Caller-requested answer tables

Ordinary public research can return a requested comparison or decision table.
The table appears before the complete canonical answer, with checked facts,
explicitly conditional proposals and unverified cells visibly distinguished.
Separately requested prose, such as a transaction outline, retains the existing
work-product contract. The table never replaces that requested artifact.

This addresses a concrete delivery gap: the evidence-only synthesis schema had
no table layout, and the answer component displayed pipe tables as paragraphs.
The retained public history contains table requests about worker shutdown,
job claiming, retry decisions and paper comparisons. That history has unknown
actor/cohort identities; it does not prove independent customer demand or model
quality. Offline tests below are contract checks, not live answer evaluations.

## Admission and review

- `parseAnswerTableRequest` recognizes finite English/Vietnamese original-caller
  directives. Exact original question bytes, including URLs and source versions,
  bind the request digest. Quotes, code, source envelopes, negation and independently
  bounded word/bullet/sentence formats do not activate table delivery.
- Existing private, prepared/augmented, teaching, targeted, decision-brief and
  unattended engine boundaries remain in `runAgent`. Source/model text cannot
  opt in. The parser is not a general natural-language intent classifier.
- The existing generation call may propose 2–5 columns and 1–8 rectangular rows.
  Facts cells refer to original evidence-array positions; they cannot introduce
  rewritten facts. Labels are subjects/categories only. Proposals require exact
  factual premises and explicit hypothetical conditions. Missing findings use
  an unknown cell, which does not establish a negative fact.
- The existing independent evidence-review call receives the immutable complete
  question/layout/premises and original factual context. It must judge the headers,
  requested dimensions and every cell's association, content, conditions and
  language. A duplicate, missing, stale or foreign review cannot create a runtime
  delivery capability. A rejected label or layout withholds the table; rejected
  factual/proposal cells become explicit unknowns in place.
- Transport input bounds, the 32 KB review bound and both existing output caps
  remain unchanged. Table additions cannot truncate factual rows/context, add a
  model call, retry a provider ceiling or bypass an unavailable review. A compound
  work product shares these same two calls; either addition may be withheld.

## Final evidence and money

Final statement admission, claim coverage, accepted markers and a unique physical
source/item/version identity still gate every populated cell. A proposal loses
delivery if any factual prerequisite is withheld. Runtime review capabilities
cannot be reconstructed from receipt JSON or reused after mutation.

The table is added only after canonical attribution and settlement. Its repeated
references cannot change source reads, support scores, contribution weights,
creator rewards, payment requests or receipts. The full canonical answer, including
unresolved targets, reading limitations and payment notices, remains intact below.
An invalid/oversized table produces an honest unavailable-table notice. No factual
qualification or condition is clipped to make the projection fit.

## Display and supported surfaces

The shared answer component renders bounded pipe tables as semantic `table`,
`thead`, `th scope=col` and `td` elements in a named, keyboard-focusable horizontal
scroll region. Literal source pipes, Markdown delimiters and apparent citations
stay text; genuine evidence controls retain the existing source inspector callback.
Malformed/ragged tables remain visible as ordinary text, never raw HTML.

The same Markdown answer travels through API/SSE, persistence, report export and
research receipts; internal review packets are not added to public schemas.
Web readers and desktop web views share the component. CLI, MCP, extension and
bot consumers retain their existing Markdown/text/report handoff roles and payment
contracts. This source change allocates no release version or deployment authority.

Tests cover original-caller admission, immutable review binding, final evidence
loss, model input/output failures, exact source text and citation controls, and
paired real orchestration with unchanged factual/financial results. Compound table
and outline delivery is tested together. Retained offline study results and their
archives are checked independently; no model-quality or real-usefulness claim is
inferred from those fixtures.
