# Opt-in public researcher profiles (#264)

This is ordinary-storage **source preparation**, with both `KERYX_PUBLIC_PROFILES_ENABLED` and `KERYX_RUN_PRIVACY_ENABLED` required explicitly. Both remain OFF unless the owner separately authorizes a rollout. This change does not activate production privacy, execute a target migration, enroll native/private storage, backfill profiles or change any run's visibility. Missing capabilities fail closed: HTML/image return 404, public JSON returns 503, and profiles add no sitemap entries. Invalid/unknown handles return 404 when the capability is present.

## Publication and ownership

The signed-wallet owner visits `/me/public-profile`, after saving a handle through the existing `/me/profile` authority. The editor starts unpublished and requires an explicit selection and Publish action. `GET/PUT/DELETE /api/me/public-profile` requires a live revocable SIWE session, an expected-wallet precondition, and same-origin writes. A bearer API key does not grant new publication authority. Profile fields are read from the existing private profile; verified links come only from the existing verified GitHub/ORCID identities. A profile assertion is not evidence of a legal identity or affiliation. No owner-assignment/consent authority is invented.

`PUT` accepts only `{published, fields, runIds, revision}`. The five selectable fields are display name, about, purpose, verified links and ledger aggregates. At most 50 unique existing owned run IDs can be selected. Each selected ID is checked against the existing recorded-owner or immutable receipt-claim proof. Claiming never establishes a payer. A revision precondition prevents a stale write from republishing after unpublish. Revoked/expired sessions are rechecked in the write transaction after awaited ownership work. A handle rename hides the old and new public page until the owner republishes; deleting the authoritative profile cascades publication metadata.

## Public projection and revocation

`/u/<handle>`, `/api/u/<handle>`, the per-handle Open Graph image and `/sitemap.xml` recheck publication on every request. There is no profile cache or regenerated sitemap interval. `DELETE` revokes publication immediately for subsequent origin reads; it does not retract copies already saved by external readers. The public projection includes only selected fields and selected runs whose current visibility is explicitly PUBLIC and not erased. PRIVATE, UNLISTED, historical missing-sidecar and no-longer-owned runs are omitted before run text is loaded. SQLite rechecks publication, identity links, original run bytes, ownership columns and visibility after asynchronous reads; PostgreSQL holds publication/profile/run/privacy rows for the RPC transaction.

The run projection contains question, date, stored caller surface, stored network evidence, funding label, ownership method, citation names/markers/safe HTTPS links and the existing report/receipt paths. It never includes answers, traces, wallets, authorization nonces, recovery packets, claim tokens or private profile activity. Citation URLs with credentials or query parameters are omitted. Network is derived from stored usage/payment networks; missing, invalid or conflicting evidence is labelled unrecorded, never replaced by today's server configuration. Offline runs are labelled simulation. Stored treasury funding is labelled treasury sponsored; other validated stored sponsorship is labelled recorded sponsorship with the treasury payer unproved. Unknown original ownership methods remain unknown. There is no new identity inference or claim transfer.

The page uses existing semantic headings, named sections, lists, dates and links; narrow columns wrap text and amounts. The new profile screen is English; this source does not edit the locale helpers or API/MCP locale adapters owned by #276. Open Graph/JSON-LD include only selected profile text/verified links and escape script data through the existing safe JSON helper. Compiled phone-width/browser acceptance remains distinct from SSR/source tests.

## Exact ledger basis

Ledger aggregates are a separate explicit opt-in, explained in the editor. They cover wallet-wide **recorded settled fetch/citation events**, including aggregate amounts associated with private runs without exposing their identifiers or text. They do not claim that every payment was made by this person. Reader spending uses the actual recorded payer wallet; creator earnings use the actual recorded creator payee wallet, including historical payments for a since-removed source. Registering a profile does not register a source or prove content ownership. Treasury-funded runs are excluded from reader spending and shown separately as sponsored creator payments attributed to this run owner.

Mainnet and testnet are separate. Only positive amounts with the existing settled bit, `settlement_status='settled'` and a nonempty confirmation reference count. Pending, failed, simulated, offline, inbound and operating-fee events are excluded. Amounts accumulate as exact integer micro-USDC; invalid sub-micro precision produces Unavailable, not rounding or a fabricated total. Empty matching sets produce zero. No payment, order, receipt, balance, custody or treasury state is changed, and these stored records are not a fresh chain reconciliation.

## Storage and surface boundaries

Ordinary SQLite installs only its additive publication metadata after exact source-known privacy/schema checks. Unknown publication schema/triggers or sealed storage refuse without repair. Supabase uses one fixed service-role RPC and source-only migration `0091_public_researcher_profiles.sql`; no REST fallback, retry, native domain extension or target DDL is included. The migration depends on the existing private profile, verified identity, claims and privacy contracts. Its source-created immutable catalog seal refuses publication relation/function/ACL/trigger drift rather than adopting it. RLS and grants keep publication writes/owner settings unavailable to anonymous/authenticated SQL roles. PostgreSQL runtime migration and concurrency verification are still required before any separately authorized rollout.

Web owners publish through the private editor; unauthenticated web/API readers receive the same bounded public JSON. CLI, Desktop, extension, bots, stdio/hosted MCP and A2A gain no profile publication tool, private field enumeration or inferred ownership permission. They may consume the public page/JSON under the same public contract; their existing research and payment roles are untouched. Private recovery/native operators have no fallback into ordinary publication. Existing #266 PRIVATE/UNLISTED/PUBLIC defaults and every original money/claim authority remain unchanged.

## Validation and delivery

Focused tests cover visibility levels, unknown handles, ownership/claims, selection, stale writes, immediate unpublish, revocation during I/O, rename/delete, verified-link removal, exact ledger amounts and Supabase closed packets/acknowledgments. SSR tests cover accessible regions, safe owner text, exact amount display and truthful labels. Source contract tests are not a PostgreSQL execution receipt. Native command receipts and any denied tests/build are retained in the independent owner handoff. Actual hosted CI, independent review, approved schema/capability rollout, compiled phone verification and deployment remain root-owned; #264 stays open. No paid or human trial has been added as an acceptance criterion.
